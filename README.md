## โครงงานนี้คืออะไร

นักเรียนระดับมัธยมศึกษาตอนปลายต้องเรียนหลายรายวิชาและเตรียมตัวสอบหลายรูปแบบ ทำให้แบ่งเวลาอ่านหนังสือได้ยาก
บางคนไม่รู้ว่าควรเริ่มอ่านวิชาใดก่อน หรือวางแผนไว้แล้วแต่ติดตามไม่ได้ว่าทำตามแผนไปแล้วมากน้อยเพียงใด

เว็บไซต์นี้จึงรวม **3 เรื่องไว้ในระบบเดียว** ตามขอบเขตของโครงงาน

| ขอบเขตในรายงาน | สิ่งที่ระบบทำได้จริง |
|---|---|
| 1.3.2.1 การวางแผนการอ่านหนังสือ | บันทึกแผนโดยกำหนดรายวิชา วันที่ เวลาเริ่ม–สิ้นสุด และหัวข้อที่จะอ่าน |
| 1.3.2.2 การกำหนดเป้าหมายการเรียน | ตั้งเป้าหมายทั้งระยะสั้นและระยะยาว วัดผลเป็นชั่วโมง/ครั้ง/บท/ข้อ พร้อมกำหนดวันครบกำหนด |
| 1.3.2.3 การติดตามความก้าวหน้า | คำนวณเปอร์เซ็นต์ที่ทำได้ตามแผน กราฟเวลาอ่านรายวัน สถิติแยกรายวิชา และจำนวนวันที่อ่านต่อเนื่อง |

### ส่วนที่พัฒนาต่อจากรายงาน

รายงานโครงงาน (หัวข้อ 5.2) ระบุว่าผลงานเดิมหยุดอยู่ที่ **ต้นแบบ (Mockup)** เท่านั้น
ยังไม่มีระบบบันทึกข้อมูลผู้ใช้ การแจ้งเตือน และการคำนวณความก้าวหน้าจริง
และหัวข้อ **5.3.2 "แนวทางในการพัฒนา"** เสนอไว้ 8 ข้อ — ซอร์สโค้ดในที่นี้ทำครบทั้ง 8 ข้อแล้ว

| ข้อเสนอแนะในรายงาน (5.3.2) | สถานะ |
|---|---|
| 1. พัฒนาต้นแบบให้เป็นเว็บไซต์ที่ใช้งานได้จริง | ทำแล้ว — มีระบบสมาชิก ข้อมูลของแต่ละคนแยกกัน |
| 2. ระบบบันทึกตารางอ่านหนังสือ (วิชา วันที่ เวลา รายละเอียด) | ทำแล้ว — หน้า "วางแผนการอ่านหนังสือ" |
| 3. ระบบเป้าหมายระยะสั้น/ระยะยาว และแก้ไขได้ | ทำแล้ว — หน้า "เป้าหมายการเรียน" |
| 4. ระบบติดตามความก้าวหน้าแบบเปอร์เซ็นต์และกราฟ | ทำแล้ว — หน้า "ติดตามความก้าวหน้า" (กราฟ SVG เขียนเอง) |
| 5. ระบบแจ้งเตือนเมื่อถึงเวลาอ่าน / ใกล้ครบกำหนด | ทำแล้ว — แจ้งเตือนผ่านเบราว์เซอร์ ล่วงหน้า 10 นาที |
| 6. ระบบสรุปผลว่าอ่านวิชาใดไปแล้วบ้าง | ทำแล้ว — หน้า "สรุปผลการอ่าน" |
| 7. ใช้งานได้ทั้งคอมพิวเตอร์ มือถือ และแท็บเล็ต | ทำแล้ว — ออกแบบแบบ responsive และทดสอบจริงทั้ง 2 ขนาดจอ |
| 8. ปรับปรุงตามความคิดเห็นผู้ใช้อย่างต่อเนื่อง | โครงสร้างโค้ดพร้อมต่อยอด มีชุดทดสอบอัตโนมัติ 52 รายการรองรับการแก้ไข |

> เว็บไซต์ Notion Student Planner Templates ถูกใช้เป็น **แนวทางการออกแบบ** เรื่องการจัดข้อมูลไว้ในหน้าเดียว

## จุดเด่นทางเทคนิค: ไม่ใช้ dependency เลยแม้แต่ตัวเดียว

โครงงานนี้เขียนด้วย **Node.js ล้วน ๆ ไม่มีไฟล์ `node_modules`** ใช้เฉพาะโมดูลที่ติดมากับ Node เท่านั้น

| ใช้อะไร | แทนอะไร |
|---|---|
| `node:http` | Express / Fastify |
| `node:sqlite` | better-sqlite3 / MySQL / PostgreSQL |
| `node:crypto` (scrypt) | bcrypt / argon2 |
| `node:test` | Jest / Mocha |
| HTML + CSS + JavaScript ล้วน | React / Vue / Vite / webpack |
| กราฟ SVG ที่เขียนเอง (~120 บรรทัด) | Chart.js / D3 |

**ทำไมถึงเลือกแบบนี้**

1. **ประหยัดแรม** — ไม่มีโค้ดส่วนเกินให้โหลดเข้าหน่วยความจำ จึงรันบนโฮสต์ฟรีที่มีแรมจำกัดได้
2. **ปลอดภัยกว่า** — ไม่มีโค้ดของคนอื่นในระบบ จึงไม่มีความเสี่ยงจากช่องโหว่ของ package ภายนอก
   (supply chain attack) ซึ่งเป็นภัยที่พบบ่อยที่สุดอย่างหนึ่งในปัจจุบัน
3. **ติดตั้งง่าย** — ไม่ต้องรัน `npm install` ไม่ต้อง build โคลนมาแล้วสั่ง `npm start` ได้เลย
4. **ตรวจสอบได้ทั้งหมด** — ครูและเพื่อนอ่านโค้ดได้ครบทุกบรรทัด ไม่มีส่วนที่เป็นกล่องดำ

### ผลการวัดการใช้หน่วยความจำจริง

วัดบนเครื่อง Linux ด้วย Node.js v22

| สถานการณ์ | หน่วยความจำที่ใช้ (RSS) |
|---|---|
| ตอนเริ่มต้น ยังไม่มีผู้ใช้ | **67 MB** |
| หลังผู้ใช้ 20 คน สร้างแผน 1,200 รายการ เป้าหมาย 100 รายการ รวม 1,960 คำขอ | **110 MB** |
| ขนาดฐานข้อมูลของข้อมูลชุดนั้น | 380 KB |

หน่วยความจำส่วนที่เป็น JavaScript ใช้เพียงประมาณ **8 MB** เท่านั้น (ตรวจแล้วว่าไม่มีการรั่วไหล)
ส่วนที่เหลือคือตัว Node.js เองและหน่วยความจำที่ scrypt ใช้ตอนแฮชรหัสผ่าน

ค่านี้อยู่ในระดับที่ **แพ็กเกจฟรีของ Fly.io (256 MB) รับไหวสบาย ๆ** จึงไม่จำเป็นต้องเสียเงินซื้อเซิร์ฟเวอร์

> **หมายเหตุเรื่องการปรับแต่ง**
> ค่า `UV_THREADPOOL_SIZE=2` และ `MALLOC_ARENA_MAX=2` ใน `Dockerfile` และ `fly.toml` มีผลจริง
> จากการวัดพบว่าถ้าไม่ตั้งค่านี้ หน่วยความจำสูงสุดจะขึ้นไปถึง 148 MB แต่เมื่อตั้งแล้วเหลือ 110 MB
> เหตุผลคือ scrypt จองหน่วยความจำ 16 MB ต่อการแฮช 1 ครั้ง และงานนี้ถูกกระจายไปยังชุดเธรดเบื้องหลัง
> ยิ่งมีเธรดมาก ตัวจัดการหน่วยความจำก็ยิ่งกันพื้นที่ค้างไว้มากตามไปด้วย

## การนำขึ้นโฮสต์ฟรี

### แนะนำ: Fly.io

**เลือก Fly.io เป็นตัวเลือกหลักเพราะแพ็กเกจฟรีมี "volume ถาวร"** ซึ่งจำเป็นสำหรับ SQLite
ที่เก็บข้อมูลไว้ในไฟล์ ถ้าใช้โฮสต์ที่ดิสก์เป็นแบบชั่วคราว ข้อมูลของนักเรียนทุกคนจะหายทุกครั้งที่ deploy ใหม่

```bash
# 1. ติดตั้งเครื่องมือและเข้าสู่ระบบ
curl -L https://fly.io/install.sh | sh
fly auth signup      # หรือ fly auth login ถ้ามีบัญชีแล้ว

# 2. แก้ชื่อแอปในไฟล์ fly.toml ให้เป็นชื่อที่ยังไม่มีคนใช้
#    เช่น app = "study-planner-sk2569"

# 3. สร้างแอป (อย่าเพิ่ง deploy)
fly launch --no-deploy --copy-config

# 4. สร้าง volume ถาวรขนาด 1 GB สำหรับเก็บฐานข้อมูล
fly volumes create study_planner_data --size 1 --region sin

# 5. ตั้งกุญแจลับ (สำคัญมาก ห้ามข้ามขั้นตอนนี้)
fly secrets set SESSION_SECRET="$(openssl rand -base64 48)"

# 6. ตั้ง origin ของเว็บให้ตรงกับที่อยู่จริง เพื่อให้การป้องกัน CSRF ทำงานเข้มที่สุด
fly secrets set APP_ORIGIN="https://ชื่อแอปของคุณ.fly.dev"

# 7. นำขึ้นเซิร์ฟเวอร์
fly deploy
```

เสร็จแล้วเปิดใช้งานได้ที่ `https://ชื่อแอปของคุณ.fly.dev`

### โฮสต์ฟรีเจ้าอื่น — ข้อควรระวังสำคัญ

| โฮสต์ | ใช้ได้ไหม | หมายเหตุ |
|---|---|---|
| **Fly.io** | ใช้ได้ดี | มี volume ถาวร แรม 256 MB เพียงพอ (แอปใช้ 110 MB) |
| **Oracle Cloud Always Free** | ใช้ได้ดี | เป็นเครื่อง VM เต็มรูปแบบ มีดิสก์ถาวร แรมเยอะ |
| **Render (แพ็กเกจฟรี)** | **ต้องระวัง** | ดิสก์เป็นแบบชั่วคราว **ข้อมูลจะหายทุกครั้งที่ deploy หรือเครื่องรีสตาร์ท** ถ้าจะใช้ต้องต่อ Persistent Disk เพิ่ม (เสียเงิน) |
| **Vercel / Netlify** | **ใช้ไม่ได้** | ออกแบบมาสำหรับเว็บที่ไม่มีสถานะ (serverless) เขียนไฟล์ถาวรไม่ได้ |
| **Raspberry Pi / เครื่องที่โรงเรียน** | ใช้ได้ดี | เหมาะมาก เพราะแอปกินแรมน้อยและไม่ต้องพึ่งอินเทอร์เน็ต |

### ตัวแปรที่ตั้งได้ (environment variables)

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `PORT` | `3000` | พอร์ตที่เปิดรับ |
| `HOST` | `0.0.0.0` | ที่อยู่ที่ผูกไว้ |
| `NODE_ENV` | `development` | ตั้งเป็น `production` เมื่อใช้งานจริง |
| `SESSION_SECRET` | สุ่มสร้างเอง | **ตั้งเองเสมอเมื่อใช้งานจริง** ยาวอย่างน้อย 32 ตัวอักษร |
| `APP_ORIGIN` | อนุมานจาก Host | ที่อยู่จริงของเว็บ เช่น `https://example.fly.dev` ใช้ตรวจ CSRF |
| `TRUST_PROXY` | เปิดเมื่อ production | เปิดเมื่ออยู่หลัง reverse proxy เพื่ออ่าน IP จริง |
| `SECURE_COOKIES` | เปิดเมื่อ production | บังคับให้คุกกี้ส่งผ่าน HTTPS เท่านั้น |
| `DATA_DIR` | `./data` | ที่เก็บฐานข้อมูลและกุญแจลับ |
| `SESSION_IDLE_DAYS` | `7` | ไม่ใช้งานกี่วันแล้วหลุดจากระบบ |
| `SESSION_ABSOLUTE_DAYS` | `30` | อายุสูงสุดของ session |
| `AUTH_RATE_CAPACITY` | `10` | จำนวนครั้งที่เข้าสู่ระบบ/สมัครได้ต่อ 5 นาทีต่อ IP |
| `GLOBAL_RATE_CAPACITY` | `240` | จำนวนคำขอสูงสุดต่อนาทีต่อ IP |
| `UV_THREADPOOL_SIZE` | `4` (ของ Node) | แนะนำ `2` เพื่อประหยัดแรม |
| `MALLOC_ARENA_MAX` | ของระบบ | แนะนำ `2` เพื่อประหยัดแรม |

### ลำดับด่านตรวจของทุกคำขอ

```
คำขอเข้ามา
   ↓ 1. จำกัดอัตราต่อ IP           กันการยิงถล่มเซิร์ฟเวอร์
   ↓ 2. ตรวจ CSRF                  กันเว็บอื่นสั่งงานแทนผู้ใช้
   ↓ 3. ตรวจ session จากคุกกี้      รู้ว่าใครเป็นใคร
   ↓ 4. ตรวจสิทธิ์เข้าถึง            เส้นทางนี้ต้องเข้าสู่ระบบหรือไม่
   ↓ 5. อ่านและตรวจสอบข้อมูล        จำกัดขนาด ตรวจชนิดและช่วงของทุกค่า
   ↓ 6. ทำงานจริง                  ทุกคำสั่ง SQL กรองด้วย user_id เสมอ
ตอบกลับพร้อม security headers ครบชุด
```

## ความปลอดภัย

ระบบความปลอดภัยทั้งหมดอธิบายไว้ละเอียดใน **[SECURITY.md](./SECURITY.md)** ซึ่งครอบคลุม

- การเก็บรหัสผ่านด้วย scrypt และการป้องกันการเดารหัสผ่าน
- การจัดการ session และคุกกี้
- การป้องกัน CSRF, XSS, SQL Injection, IDOR และ Path Traversal
- การจำกัดอัตราการเรียกใช้และการล็อกบัญชีชั่วคราว
- **ตารางเชื่อมโยงมาตรการแต่ละข้อกับชุดทดสอบที่พิสูจน์ว่าใช้งานได้จริง**

มาตรการเหล่านี้ไม่ได้เขียนไว้เฉย ๆ แต่มีชุดทดสอบ 35 รายการที่ **จำลองการโจมตีจริง**
แล้วตรวจว่าระบบปฏิเสธถูกต้องหรือไม่ เช่น พยายามอ่านข้อมูลของผู้ใช้คนอื่น
พยายามอ่านไฟล์ซอร์สโค้ดของเซิร์ฟเวอร์ และพยายามเดารหัสผ่านรัว ๆ

## ข้อจำกัดที่ควรทราบ

- **รองรับผู้ใช้พร้อมกันในระดับหลักร้อย** SQLite เหมาะกับงานขนาดนี้มาก แต่ถ้าต้องรองรับผู้ใช้หลักหมื่นพร้อมกัน
  ควรเปลี่ยนไปใช้ PostgreSQL
- **ทำงานเป็นโปรเซสเดียว** จงใจออกแบบเช่นนี้เพื่อประหยัดแรม ถ้าต้องการรองรับมากขึ้นควรเพิ่มเครื่อง
  แล้วย้ายฐานข้อมูลออกไปไว้ภายนอก
- **การแจ้งเตือนทำงานเมื่อเปิดหน้าเว็บไว้** เพราะใช้ Notification API ของเบราว์เซอร์
  ถ้าต้องการแจ้งเตือนแม้ปิดเบราว์เซอร์แล้ว ต้องเพิ่ม Service Worker และระบบ Web Push
  ซึ่งจะทำให้ระบบซับซ้อนและใช้ทรัพยากรมากขึ้น
- **ยังไม่มีระบบกู้คืนรหัสผ่านทางอีเมล** เพราะต้องพึ่งบริการส่งอีเมลภายนอก
  ปัจจุบันหากลืมรหัสผ่านต้องให้ผู้ดูแลระบบช่วยแก้ไขในฐานข้อมูลโดยตรง
